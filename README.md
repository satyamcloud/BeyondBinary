# Beyond binary labels: Hinglish misinformation veracity from original social posts

Dataset, code and saved predictions for the paper *Beyond binary labels: classifying Hinglish
misinformation veracity from original social posts* (Sunderam, Garg, Dubey).

The dataset has **568 claims**: the original social media post embedded in a fact-checking article
(not the fact-checker's commentary), labelled **False** (475) or **Not-Clearly-False** (93, a composite of
Misleading, Missing Context, Hard to Categorise, Partially True and True verdicts). Sources: Alt News (512 rows) and
Fact Crescendo (56 rows, minority verdicts only).

**Dataset archive:** the dataset is also archived on Zenodo, DOI [10.5281/zenodo.23300178](https://doi.org/10.5281/zenodo.23300178). In this released version, user `@handles` in the `text` column are replaced with `@user` (342 mentions in 134 rows). The models in the paper were trained on the original, unmodified text, so results on this file may differ slightly. Labels, sources and all other fields are unchanged. See `DATA_LICENSE.md` for terms.

## Reproducing the results

`python scripts/09_evaluate_and_plot.py` recomputes every reported number from the saved predictions
(no GPU needed): per-fold and pooled macro-F1, the confusion matrices, and the paired t-test (t = 0.973, p = 0.386).

To rebuild the dataset or retrain, run the scripts in order. Set `PROJECT_DIR` to the folder for the intermediate CSVs.

1. `01_scrape_altnews.py`: Alt News archive listings and article text (checks `robots.txt` first)
2. `02_enrich_verdicts.py`: ClaimReview verdicts from each article's JSON-LD
3. `03_extract_altnews_posts.py`: embedded post text (`blockquote.twitter-tweet`)
4. `04_extract_factcrescendo_posts.py` and `05_retry_factcrescendo.py`: the same for Fact Crescendo
5. `06_merge_sources.py`: merge, label, deduplicate
6. `07_clean_and_filter.py`: strip links, drop rows under 20 characters, write the final dataset
7. `08_train_kfold.py --model muril|mbert`: stratified 5-fold fine-tuning (GPU)
8. `09_evaluate_and_plot.py`: metrics, tests and figures

## Known limits of reproducibility

- Only the fold split is seeded (`random_state=42`). Model initialisation and batch order are not, so retraining
  follows the protocol but will not reproduce the exact per-fold scores; the saved predictions do.
- Steps 1 to 5 fetch live websites. Pages change or disappear, so a re-scrape will not return exactly 568 rows.
- The Fact Crescendo candidate list was built interactively in the notebook from the Google Fact Check
  Markup Tool feed; the resulting URL list is provided but that step has no standalone script.
- The scripts were assembled from the notebook cells. Only `09_evaluate_and_plot.py` has been run end to end.
- Source and label are confounded: all 56 Fact Crescendo rows are Not-Clearly-False. See the paper's Limitations section.
